# 原稿向けの規範（書籍の章とブログ記事）

このファイルの「節」は、見出しから次の見出しまでの範囲を指す。

## 整形

- 後の論証で使わない補足（用語の由来、定式化の名称）は脚注（`[^ラベル]`）に書く。
- 導入済みの語を話題として指すとき、引用するとき、通称を書くときは「」を使う。
- 人物は原綴りで書く（Dijkstra）。人名を冠した概念は、定着したカタカナで書く（「ダイクストラ法」）。

## 段落と論証

- 段落の最初の文で、その段落が何の話かわかるようにする。
- 前の段落と逆接、例示、帰結の関係にある段落は、先頭の接続表現で関係を示す（「しかし」「実際」「であれば」）。
- 反論と疑念を処理してから結論を置く。結論、反論の処理、結論の言い直しの順にしない。
- 譲歩（「確かに〜」）は事実の確認にとどめる。著者があとで覆す見方は、著者の声で断定せず、読者や通説の声に帰属させる（「〜と要約できてしまうかもしれない」）。
- 何かを否定または限定するときは、否定する命題を「」で正確に書き出す。「何もかもが解決するわけではない」のような漠然とした否定で済ませない。
- 節の最後で明かす数値や事実（「ここまでわずか数十秒。」）は、手前の段落で先に書かない。

## 読み手の負荷

- 論証の中では、後の文で使わない固有名、精度、人物設定を書かない（「入社2年目のエンジニアが」）。
- 抽象的な言い回しの指す内容が一意に決まらないときは、丸括弧の同格挿入でその場で特定する。
- 新しい例や場面を足すときは、前の例と何が違い、なぜ必要かを先に書く。

## 視点と語り

- 論証の中で読者を「あなた」と呼ばず、役割名（「開発者」「読者」）で書く。二人称は場面への導入と、章や記事の結びに限る。
- 対象を「AI」「ツール」のような広い語でぼかさない。正確な名前を導入する前の仮の呼び名としてなら使ってよい。
- 術語と訳語は、その分野の文献が使う語にする（プッシュ通知は「配送」ではなく「配信」）。

## 演出

- 溜め（「ここに一つ見落としがある」）と修辞疑問は、節の結論を導く直前に、それぞれ1節に1回まで使う。
- 20字以下の体言止め（「ここまでわずか数十秒。」）と、感嘆符で終わる20字以下の一文は、それぞれ1節に1回まで使う。独立した段落にしない。
- 主張の様式を宣言する前置き（「標語として言い換えれば」）は、回数を限らず使ってよい。

## 見出し

- 見出しは、その節が答える問いか、扱う対象を指す句にする。結論の文や種別名（「補足」）にしない。

## 読者への誠実さ

現実に起きにくい例（極端な数値、まれな障害の重なり）は、その疑いを認め、現実にあり得る根拠を短く書く。
根拠は著者の断定ではなく、読者の経験に訴える事実か通説に求める（「この症状は珍しくないだろう」）。

# 日本語の規範

「書き直すときは」で始まる規則は、他人の文章を書き直すときだけに当てはまる。

## 文書の立場と文末

先に文書全体の立場を一つ決め、文末をそれに合わせる。
主語は、文末と文書の立場から誰が動くか決まるとき（決まりの手順の「〜します」なら読み手）だけ省く。

- **決まり**：読み手に従ってほしい文書（運用ルール、手順書、仕様）。決まりと手順は「〜します」（常体なら「〜する」）で書く。理由を述べる文（「〜ためです」）と、依頼の「〜してください」も使ってよい。
- **勧め**：読み手に試してほしい文書（心得、助言）。読み手の行動は「〜しましょう」「〜してください」で書き、主語のない「〜します」にしない。
- **説明**：読み手に知ってほしい文書（技術の説明、報告、体験）。文末は「〜です」「〜します」（常体なら「〜だ」「〜する」）にする。読み手に頼む動作は「〜してください」で書く。最後の1文だけは「〜しましょう」で結んでよい。

- どの立場でも、道具や処理の働き（「このツールはログを集めます」）は「〜します」で書く。
- 「です・ます」と「だ・である」を混ぜない。書き直すときは元の文書に、新しく書くときは掲載先の既存の文書に合わせる。既存の文書がなければ「です・ます」にする。
- 書き直すときは、分野名（「技術記事向け」）だけで立場を決めない。
- 書き直すときは、立場と合わない文末だけを直す。言い切りの説明を「〜できます」にしない。立場を決めきれなければ文末を変えず、別の立場で書く場合の文末案を書き手に1行で示す。

## 誰が何をどうしたか

- 述語まで書く。名詞を「の」でつないで体言止めで終える文（「キュー滞留によるメッセージ処理遅延の発生。」→「キューが滞留し、メッセージの処理が遅れた。」）を書かない。
- 道具や概念に意志を持たせない。物が主語の「〜てくれる」と「語る」を書かない（「このキャッシュが負荷を減らしてくれる」→「このキャッシュで負荷が減る」）。
- 主題の「も」は、前の文に並ぶ相手があるときだけ使う。相手がなければ「は」にする。

## 比喩動詞と英語直訳調

概念や方針が主語か目的語のとき、物理や身体の動詞は比喩になる。
物が主語の文字どおりの用法（「ファイルが壊れた」）と、体の部位を使う慣用句（「骨が折れる」「手を焼く」）は残す。

| 語（使われ方） | 書き換えの方向 |
|---|---|
| 効く（「地味に効きます」） | 何がどう良くなるか（「応答が速くなる」） |
| 静かに、黙って（「静かに壊れる」） | 気づかないうちに |
| 壊れる（「順序性が壊れる」） | 何が起きるか（「メッセージの順番が入れ替わる」） |
| 踏み込む、引き返す（「仕様に踏み込む」） | 詳しく調べる、元に戻す |
| 添える、沈黙する（「前提を添える」「サーバーが沈黙する」） | 渡す、応答しない |
| 〜を指している（point to） | 〜を表している（推測なら「〜と考えられる」） |
| 耐力のある（load-bearing）、深掘りする（delve into） | 外せない、詳しく調べる |

## 置き換える語

次の語は、何が起きたか、何をしたかを書いて置き換える。定義した術語は残す。
リンターがAI頻出語として指摘する語は、文字どおりの用法でなければ同じように扱う。

- 比喩の名詞：「落とし穴」「素通り」「入口」「核心」「主役」「構図」「線引き」
- 役割を大きく見せる名詞：ルールを指す「契約」、何を区別するか曖昧な「境界」、中身を言わない「仕組み」。数学や区域の境界と境界値は残す。
- 大げさな語：「本質」「究極」「破綻」

## 削る前置きと結び

- 前置き：「ここで注目すべきは」「近年、〜の発展は目覚ましく」「本稿では」
- 結び：「〜というわけです」「〜に他なりません」「〜の参考になれば幸いです」

## 文の長さと読点

- 60字を超える文は、「〜ので」「〜て」「〜てから」「〜が」の切れ目で分ける。切れ目がなければ残す。
- 読点は1文に0〜2個にする。列挙の読点は数えない。
- 目的語と直後の動詞のあいだに読点を打たない（「前提を、確認します」）。
- 10字未満の短文を2文続けない。
- 同じ文末（「です」「ます」「でした」「ました」「だ」「である」）を3文続けない。並列の決まりや手順なら箇条書きにする。そうでなければ2文を1文につなぐ。

## 記号と空白

- ダッシュ（「—」「―」「——」「──」）を使わず、助詞、読点、句点でつなぐ。1文につなぐと前の理由や条件（「〜ため」「〜なら」）が後ろまでかかってしまうなら、2文に分ける。
- 和文と英単語、略語、数字、コードスパンのあいだに半角空白を入れない（「このREADMEは」）。
- 箇条書きを導く文、見出しの末尾、文末にコロン（「：」「:」）を置かない。ラベルと値の区切り（「日時：10時」）は使ってよい。
- `**`のすぐ内側が記号（「」（）、。やバッククォート）で、すぐ外側が文字だと、GitHubなどでは太字にならない。かっこの内側だけを太字にするか（`**「立場」**を`→`「**立場**」を`）、句読点を太字の外に出す。どちらもできなければ、`**`の外側に半角空白を1つ入れる。

## 点検

`python3 $HOME/.claude/skills/tech-writing/scripts/yomiyasu_lint.py <ファイル>`で行単位の候補を出す。
文末の立場の混ざりは、`python3 $HOME/.claude/skills/tech-writing/scripts/yomiyasu_diff.py --endings <ファイル> [--stance=<勧め|決まり|説明>]`で候補を出す。

- このファイルの規則は、リンターの結果にかかわらず、コードブロックの外で一文ずつ手で確かめる。
- 0〜100のスコア、太字頻度、箇条書き比率は使わない。

書き直すときは、最後に`python3 $HOME/.claude/skills/tech-writing/scripts/yomiyasu_diff.py <元の文> <書き直した文> [--stance=<勧め|決まり|説明>]`を1回だけ実行する。
候補を一つずつ確かめる。SKILL.md「Revising another writer's text」の四つの性質が変わった文は、元に戻す。

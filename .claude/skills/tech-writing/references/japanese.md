## 文書の立場と文末

日本語の文は主語を省くことが多く、文末が誰が動くかを伝える。
そこで、先に文書全体の立場を一つ決め、すべての文末をそれにそろえる。
主語は、文末で誰が動くか決まらないときだけ書く。

- **勧め**：読み手に勧める、頼む文書（心得、助言）。文末は「〜しましょう」「〜してください」。
- **決まり**：決まりや手順を伝える文書（運用ルール、手順書、仕様）。文末は「〜します」（常体なら「〜する」）。
- **説明**：事実、結果、考えを伝える文書（技術の説明、報告、体験）。文末は「〜です」「〜します」（常体なら「〜だ」「〜する」）。

立場は、依頼にある載せる場所と読み手（「社内ブログ向け」「上長への報告」）、本文の手がかり（「当チームでは」などの主語、宛名、署名）の順に見て決める。
「技術記事向け」のような分野名だけでは決めない。
手がかりがなく、読み手にしてほしい行動を並べた文書は、勧めとして読む。

- SKILL.md「Complete」の手順の文は、決まりの文書では「〜します」、勧めの文書では「〜してください」で書く。
- 勧めの文書では、読み手の行動を書いた主語のない「〜します」を「〜しましょう」にする。順を追った手順と、仕組みや道具の働き（「このツールはログを集めます」）は残す。
- 決まりの文書では、決まりそのものを書いた「〜しましょう」「〜ことが重要です」を「〜します」にする。理由を述べる文と「〜してください」は残す。
- 「です・ます」と「だ・である」を混ぜない。手がかりがなければ「です・ます」にする。
- 強さを変えない（「〜しましょう」を「〜しなければなりません」にしない）。言い切りの説明を「〜できます」に変えない。
- 書き直すときは、文末が混ざっているとき、常体や箇条書きを敬体の地の文にするとき、立場が依頼と合わないときだけ文末を直す。説明を「〜します」で書いて最後だけ「〜しましょう」で結ぶ形は、混ざっていない。立場を決めきれなければ、別の立場で書く場合の文末案を書き手に1行で示す。

## 誰が何をどうしたか

- 指示語（「これ」「両者」「片方」）は、指す名詞に戻す。主語と述語のねじれを直す。
- 道具や概念に意志を持たせない（「このドキュメントが、APIの仕様を語っている」→「このドキュメントに、APIの仕様が書かれている」）。書き直すときは、元にない条件（「〜を使えば」）や可能（「〜できる」）を足さない。
- 指示語、つなぎ言葉、主題の「も」が、前後の何と何をつなぐかを確かめる（「設定を変更しました。ただし、再起動が必要です。」→「設定を変更しました。そのため、再起動が必要です。」）。
- 「適宜」「必要に応じて」は、条件と結果に書き換える。
- 書き直すときは、中身のない予告文（「注目すべき点があります」）を、予告の重みを述語に残して中身の文とまとめる。

## 比喩動詞と英語直訳調

AIが好む比喩動詞と英語の直訳は、硬い技術用語や漢語ではなく、ふだん使う言葉に戻す。

- 書き直すときは、比喩が持っていた含みを別の言葉で残す（「地味に」の目立たないが確かにある感じ、「〜てしまった」の後悔）。
- 文字どおりの用法（「時計が壊れた」）と、AI以前の文章にも見かける慣用句（「骨が折れる」「手を焼く」）は残す。
- 意味の広さを変えない。データやシステムの「壊れる」は「おかしくなる」「使えなくなる」に、「静かに」「黙って」は「気づかないうちに」にする。「整合性が失われる」「通知なく」と狭めるのは、前後からそうとわかるときだけにする。

| 語 | 書き換えの方向 |
|---|---|
| 効く（「地味に効きます」） | 目立たないながらも役に立つ |
| 倒す（「安全側に倒す」） | 安全を優先する、除外する |
| 溶かす（「時間を溶かした」） | 時間がかかってしまった |
| 潰す、踏み込む、引き返す | 直す、詳しく調べる、元に戻す |
| 添える、収斂する、沈黙する | 渡す、決まった、応答しない |
| 〜した瞬間（the moment） | 〜するとすぐに |
| 正本（single source of truth） | 信頼できる唯一の情報源 |
| 〜を指している（point to） | 〜を表している、〜と考えられる |
| 耐力のある（load-bearing） | 外せない |
| 深掘りする（delve into） | 詳しく調べる |

出典：本体「比喩動詞の具体化」、構文 原則4、語彙 §1〜2

## 要点検の語

比喩や定型として使うときだけ、ふだんの言葉に開く。
文字どおりの用法と専門用語（医学の「体温」、画像処理の「解像度」）は残す。

- 障害の比喩：「事故」→「思いがけない失敗」、「落とし穴」→「見落としやすい点」、「破綻」→「うまくいかなくなる」、「実害」→「実際の困りごと」、「素通り」→「気づかず通る」、「混ざる」→「入り込む」
- 確認の比喩：「実測」→「実際に測った値」、「疑う」→「念のため確かめる」、「照合」「突き合わせる」→「見比べる」、「断定」→「言い切る」、「取り違える」→「間違える」
- 役割や位置の比喩：「入口」→「手始め」、「土台」→「基本」、「道具」→「手段」、「核心」→「いちばん肝心なところ」、「主役」→「中心」、「構図」→「全体の関係」、「線引き」→「区切り」
- 評価の定型：「既定」→「もともとの設定」、「別物」→「まったく違うもの」、「定番」→「よく使われるもの」、「要点」→「大事なところ」、「定石」→「標準の進め方」、「桁違い」→「はるかに大きい」
- 壮大化：「真理」「真実」「結末」「宿命」「運命」「境地」「極致」「究極」「虚飾」「虚像」「美学」「深淵」「禁欲的」「優美」「冷徹」「残酷」「凝縮」「結晶」。小さな体験は素直な実感で書き、事実にない固有名詞、教訓、五感の描写を足さない。
- 質感を装う語：「手触り」「肌感」「肌感覚」「体温」「温度感」「熱量」「血の通った」「泥臭い」。前後からわかる事実か、同じ幅のふだんの言葉で書く。
- 認知を装う語：「解像度（を上げる）」「腹落ち」「メンタルモデル」「文脈」。何をどこまで調べたかを書く。
- 評価を装う語：「本質」「本質的」「地に足のついた」「等身大」。空疎な修飾なら削る。主題になっている「本質」は、「目的」のような別の概念にすり替えない。
- 比喩名詞と未定義の造語：「営み」「羅針盤」「起爆剤」「触媒」「意思決定OS」。ふだんの言葉か機能の説明で書く。

出典：語彙 §3〜5、domains/essay §1〜2、`scripts/yomiyasu_lint.py`のSLOP_WORDS

## 前置きと結び

- 前置き（「重要なのは」「結論から言うと」「正直に言うと」「避けたいのは」「ここで注目すべきは」）を削り、伝える中身から書く。
- 後置のラベル（「〜というわけです」「〜に他なりません」「面白いのはここです」）は、事実を述べる文末で閉じる。
- 一般論の前置き（「一般に〜」「現代社会において〜」「近年、〜の発展は目覚ましく」）と論文調（「本稿では」「筆者は」）を削り、課題や前提条件から書く。
- 定型の結び（「いかがでしたでしょうか」「ぜひ試してみてください」「〜の参考になれば幸いです」）、読後の効果の約束、短い記事の「まとめ」見出しを書かない。

出典：本体「セルフラベリングと否定対比の整理」、構文 原則5〜6、語彙 §6、domains/tech §1、§3、domains/business §3、domains/essay §3

## 文の長さと読点

- 一文は平均30〜45字を目安にする。60字を超える文は、後ろの文の頭に「そのため」「こうすることで」「一方で」などを置いてつながりを残せる切れ目で分ける。そのような切れ目がなければ、分けずに残す。
- 読点は1文に0〜2個にし、文頭の強調の読点（「前提を、〜」）を打たない。列挙の読点は数えない。
- 10字未満の短文を続けない。
- 硬い漢語の連続は動詞や和語に開く（「整合性を担保します」→「矛盾が生じない状態を保ちます」）。
- 同じ文末（「〜です」「〜します」など）を3文続けない。書き直すときは、ほかにも直す箇所がある文でだけ文末の言い回しを変え、勧め、決まり、説明の別は変えない。

出典：本体「文長と読点の調整」、構文 原則7〜8、domains/tech §2〜3

## 記号と空白

- ダッシュ（「—」「―」「——」）を地の文と見出しで使わず、助詞、読点、句点でつなぐ。ダッシュを外して1文につなぐと、前の理由や条件（「〜ため」「〜なら」）が後ろまでかかるなら、2文に分ける。
- 和文と英単語、略語、数字のあいだに半角空白を入れない（「この README は」→「このREADMEは」）。コードスパンの前後は対象外とする。
- 箇条書きの前置き、見出しの末尾、文末に全角コロンを置かず、句点で閉じる。
- 太字は表示される書き方にする。`**` のすぐ内側が記号（「」（）、。やバッククォート）で、すぐ外側が文字だと、GitHubなどでは太字にならない。次の順に直す。
  1. かっこの内側だけを太字にする（`**「立場」**を`→`「**立場**」を`）。
  2. 句点を太字の外に出す（`**必須です。**詳しくは`→`**必須です**。詳しくは`）。
  3. 1と2ができなければ、`**` の外側の、文字に接する側に半角空白を1つ入れる。この空白は、半角空白の規則の対象外とする。

出典：本体「装飾記号と不要な空白の排除」、構文 原則9、原則11〜12、原則14

## 点検

まず`python3 $HOME/.claude/skills/tech-writing/scripts/yomiyasu_lint.py <ファイル>`で行単位の候補を出す。
文末の立場の混ざりは、`python3 $HOME/.claude/skills/tech-writing/scripts/yomiyasu_diff.py --endings <ファイル> --stance=<勧め|決まり|説明>`で候補を出す。

- 0〜100のスコアは使わない。この規範のように規則を並べる文書では、太字頻度と箇条書き比率の警告を対象外とする。
- 「太字の印（**）が記号に接して」いるという指摘は、案のとおりに直す。
- リンターは、見出し、表、引用の行の語彙と、箇条書きの行の前置きと文末を検査しない。そこで、コードブロックの外で次を手で探す。ダッシュ、60字を超える文、読点が三つ以上ある文、擬人化、つなぎ言葉と指示語の接続先、「要点検の語」、リンターが見ない行の前置きと文末。

書き直すときは、リンターの再実行（SKILL.md「Check mode」の上限まで）を終えてから、元の文と書き直した文をファイルに保存し、`python3 $HOME/.claude/skills/tech-writing/scripts/yomiyasu_diff.py <元の文> <書き直した文> --stance=<勧め|決まり|説明>`を1回だけ実行する。
出た候補を一つずつ確かめ、意味がずれていれば元に戻す。

出典：本体「2. 実行手順」Step 3〜4
